1. 專題實作四大階段 (Phase 1 ~ Phase 4)

Phase 1：攻擊資料生成 (Offensive Generation)

目標：建立 MD-based Indirect Prompt Injection Fuzzer。
1. 設計 Prompt Injection Seed 並建立標準種子庫。
2. 規劃語意與排版 Mutation 策略。
3. 利用 Attacker AI 自動產生大量對抗性 .md 文件。

Phase 2：Agent Attack Testing

目標：測試 AI Agent 是否受文件中的 Injection 影響。
1. 建立嚴格隔離的 Sandbox 與 Mock Tools。
2. 讓 Target Agent 讀取變異文件並執行任務。
3. 觀測並記錄 Agent 是否偏離原始 Task、是否調用未授權工具。

Phase 3：建立 Attack Dataset

目標：彙整實驗數據建立標準安全數據集。
記錄每次測試的 Seed、Mutation 類型、Agent 輸入輸出、Tool Call 與任務偏離情況，計算各類變異下的初始 ASR。

Phase 4：AI Defense (Defensive Evaluation)

目標：建立 Prompt Injection 偵測與防禦系統。
利用 Dataset 進行特徵工程與風險評分，設計 Defender AI 前置審查機制；最後由 Attacker AI 再次發動全量攻擊，實證防禦後 ASR 顯著下降！

2. 專業技能與工程能力提升

AI Agent 系統與自動化 Fuzzing

掌握智慧代理人架構（OpenClaw/Agentic Workflow），學會設計結合 LLM 的自動化語意模糊測試流程。

提示工程與對抗性樣本生成

深刻理解直接與間接提示注入的攻防特徵，實作 10 大類語意混淆、角色偽冒與結構包裝的變異運算子。

安全防禦與數據集評估

構建標準化的 Attack Dataset 與雙階段 Oracle 評判邏輯，掌握以 ASR 為核心的科學量化驗證方法。

科研沙盒與倫理邊界規範

落實「去武器化」科研原則，全程採用 Mock 工具與隔離環境，確保資安研究的高度嚴謹性與可重現性。

心路歷程
與自我反思

專題的核心本質：建立完整的自動化攻防框架
專題剛起步時，我們曾思考是否只要手動寫出幾個精妙的 Prompt 攻擊成功就算達標？但在與王仁甫教授的探討中，我們深刻意識到：資安研究的價值不在於單點展示，而在於建立一套可自動化探索弱點、可量化統計、可學習防禦的完整系統體系。

體會「AI 打 AI」的前沿魅力：
透過讓 Attacker AI 擔任紅隊探索邊界，讓 Defender AI 擔任藍隊學習審查特徵，最後比對 ASR 下降幅度，這套閉環架構讓我們親身體會到下一代 AI 安全工程的精髓。從一開始對 Agent 行為不可控的迷茫，到逐步設計出客觀評判的 Oracle，每一步都是工程邏輯的躍升。

研究團隊協作（ZQ）：
在整個專題期間，團隊成員分工推進種子改寫、Fuzzer 變異腳本、數據集收集與防禦模型調優，培養了極具默契的研發協作與自主解決未知問題的韌性。

給資管系上的建議：
衷心感謝系上提供完善的專題研究資源與成果展示機會。隨著 Agentic AI 時代的來臨，建議系上未來能在課程中增加更多自主代理系統架構、API 安全與對抗性 AI 的專案實作內容，讓同學能接軌國際最前沿的技術熱點。

給學弟妹的建議：
1. 儘早動手跑實驗：概念想得再多，不如親自寫出第一版 Fuzzing 腳本跑一次 Log，真實數據會告訴你問題在哪裡。
2. 重視科研記錄與可重現性：每次測試都留下完整的日誌與元數據，這會讓你的研究成果在最後評審展現時極具說服力！
3. 享受挑戰：遇到瓶頸是探索未知的必經之路，保持好奇心與耐性，專題帶給你的收穫將遠超預期！
