1. 工作簡述與研究目標

本次實習於前瞻資安科技實驗室 NextGen InfoSec Lab（NGIS Lab）進行，指導老師為王仁甫。專題主題為「Markdown 間接提示注入 Fuzzing 與 AI 防禦研究」，研究對象是會載入第三方 Markdown 技能檔（SKILL.md）、具備持久記憶與工具呼叫能力的 LLM Agent。

這三項能力結合起來，讓攻擊者有機會透過一份被汙染的文件，在之後的回合才觸發延遲的多步攻擊。本專題提出一套可重現、完全去武器化的 fuzzing 方法，把攻擊拆成三個可量測的階段：

F5

惡意技能供應鏈

Agent 載入含有注入內容的 SKILL.md。

F2

記憶污染

Agent 在第一回合把注入內容寫進記憶。

F3

工具濫用

第二回合使用者只提出一般問題，Agent 卻依記憶呼叫被注入的工具。

2. 四個研究問題

  1. 攻擊可行性：注入能不能讓 Agent 完成 F5 → F2 → F3？
  2. 變異穩健性：AI 產生的變異能不能提高攻擊成功率？不同變異算子的效果有什麼差別？
  3. 偵測可行性：靜態規則與 Defender AI 能不能在執行前偵測出注入？
  4. 閘門可行性：把 Defender AI 接成前置 gate，能不能擋下攻擊，同時不影響正常文件的使用？

3. 研究規範

只用 mock 工具

所有工具呼叫只記錄成惰性事件（executed: false），不連網、不存取檔案、不執行任何真實動作。結果代表「模型做出了誤用的決定」，不是真的造成損害。

語料去武器化

不複製 InjecAgent 的原始攻擊文字，只保留結構與攻擊類型；以 MEMORY_TEST、TOOL_TEST 這類測試標記取代真實的惡意內容。

不手寫越獄

不為了逼出單筆成功而加強注入文字。固定攻擊強度、語料與流程，跨模型的攻擊成功率（ASR）才能比較。

規格先於結果

每一版 harness 的規格都在跑任何結果之前寫定，避免看到結果才調整判定標準。

不洩漏攻擊意圖

模型看得到的文字中，seed 與攻擊家族名稱都換成不透露資訊的雜湊碼。

可追溯

每筆變異保留來源紀錄；實驗的輸出、script 與 log 都保存在 VM 上，數字都能回溯到原始 run 檔；結果附上模型名稱、API 提供者、日期與 runner 設定。
