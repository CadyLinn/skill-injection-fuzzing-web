AI Agent Security

從 Fuzzing 到 Indirect Prompt Injection 的 AI 攻防研究

指導老師：王仁甫 教授
專題代號：【ZQ】 ｜ 研究成員：林郁庭、謝雨澄
核心問題：如果 AI Agent 讀取的外部 Markdown / Skill 資料中藏有惡意指令，AI 是否會把「資料」誤認成「指令」並偏離原始任務？

一句話理解整個專題

我們先準備帶有 Prompt Injection 特徵的 Markdown 文件當作 Seed，利用 AI Fuzzing（Attacker AI） 自動產生大量變異版本，讓 Target AI Agent 讀取並觀察哪些輸入會使 Agent 偏離原本任務；接著把攻擊結果建立成 Attack Dataset，再利用這些資料設計 Defender AI 防禦機制，最後重新攻擊並比較防禦前後的 Attack Success Rate（ASR）。

核心流程：Seed → AI Fuzzing → 對抗性 MD → 攻擊 Agent 找弱點 → 收 Dataset → AI 防禦 → 驗證 ASR 下降

AI vs AI

Attacker AI ⚔️ Defender AI

核心研究問題 (Research Question)

研究想探討的問題

"Can an AI-driven fuzzing framework automatically discover indirect prompt-injection vulnerabilities in AI agents, and can an AI-based defense system detect and mitigate these attacks?"

中文：AI 驅動的 Fuzzing Framework 是否能自動發現 AI Agent 的間接提示注入弱點，並利用 AI 防禦機制偵測與降低這類攻擊的成功率？

現在的 AI Agent 不只會回答問題，還會讀取 Markdown、SKILL.md、搜尋網頁、使用 RAG 或呼叫 Tools 執行任務。若外部資料夾雜隱藏指令，Agent 能否區分「這是我要讀的資料」還是「這是我要遵守的指令」？

Direct Prompt Injection

使用者直接下達惡意指令（如 Ignore previous instructions）。

Indirect Prompt Injection

指令潛藏在外部 Markdown、Skill、Email 等資料中，被 Agent 讀取時觸發。

AI-based Fuzzer

以 Attacker AI 自動改變語意、Markdown 結構、語氣，探索邊界盲點。

Defender AI

在 Agent 載入前進行預先審查，區分 Benign、Suspicious 與 Malicious。

AI vs. AI 完整攻防閉環架構

1. 🔴 Attacker AI

利用種子進行語意、格式變異，生成大量 Fuzzed Markdown 文件。

→
2. 🤖 Target AI Agent

在沙盒中讀取文件並執行原始任務，觀察是否受誘導偏離或越權。

→
3. 📊 Attack Dataset

收集行為日誌、任務偏離標記與攻擊成功案例，計算初始 ASR。

→
4. 🔵 Defender AI

特徵工程與前置攔截審查；重新攻擊驗證防禦後 ASR 是否顯著下降。
